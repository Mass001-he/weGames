# 象棋规则实现说明

本目录包含中国象棋的核心走法规则和胜负判定逻辑。所有逻辑均为纯 TypeScript 实现，不依赖任何 UI 框架。

## 1. 架构说明

采用**策略模式**实现走法验证：
- `IMoveValidator`: 所有验证器的基类接口。
- `MoveValidator`: 验证器工厂/外观，根据棋子类型分发请求。
- `GameRules`: 统筹全局规则，包括“将军”、“困毙”、“飞将”等。

## 2. 棋子走法 (Specific Validators)

| 棋子 | 类名 | 规则描述 | 特殊限制 |
| :--- | :--- | :--- | :--- |
| **帅/将** | `GeneralValidator` | 走一步，走直线 | 限制在九宫格内 (Red: x3-5, y7-9; Black: x3-5, y0-2) |
| **仕/士** | `AdvisorValidator` | 走一步，走斜线 | 限制在九宫格内 |
| **相/象** | `ElephantValidator` | 走“田”字 (2格对角线) | 不能过河；**塞象眼**（田字中心有子不能走） |
| **马** | `HorseValidator` | 走“日”字 (2x1) | **蹩马腿**（移动方向紧邻点有子不能走） |
| **车** | `ChariotValidator` | 走直线，无步数限制 | 不能跳跃（路径必须无子） |
| **炮** | `CannonValidator` | 走直线 | 移动时路径无子；吃子时必须隔一个子（**炮架**） |
| **兵/卒** | `SoldierValidator` | 走一步 | 过河前只能直走；过河后可直走或横走；永远不能后退 |

## 3. 全局规则 (GameRules)

### 3.1 走法有效性 (`isMoveValid`)
一个移动被认为是有效的，必须同时满足：
1.  **符合棋子基本走法**：通过对应的 Validator 验证。
2.  **不违反自杀规则**：移动后，己方老将不能处于被将军的状态。
3.  **不违反飞将规则**：移动后，若导致双方老将直接对面且中间无子，则无效。

### 3.2 将军检测 (`isKingInCheck`)
遍历敌方所有棋子，检查是否存在至少一个棋子能够按照其基本走法“吃掉”己方老将。

### 3.3 胜负判定 (`checkGameOver`)
中国象棋规则：**困毙即负**。
- 如果轮到某方走棋，但该方没有任何合法的走法（所有走法都会导致被将军），则判负。
- 不同于国际象棋的“逼和（Draw）”，这在中国象棋中是“输棋”。
